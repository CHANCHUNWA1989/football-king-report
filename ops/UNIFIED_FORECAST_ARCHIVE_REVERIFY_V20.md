# V20 archived forecast fresh verification bridge

V19 locates possible original paired documents; V20 decodes only four proof members into a private temporary directory and invokes the existing forecast_provenance_audit CLI. It requires explicit independently obtained source/workflow commit pins and uses the archived run/attempt path. Rechecks the fresh report's three subject hashes, bundle hash, run metadata and exact matched ledger case/index. Saved verification JSON is never passed to the verifier. Only a fresh successful audit can report a witness before the recorded kickoff; this is not authenticated actual kickoff, result, or full sample admission. Run: python -m ops.research_forecast_archive_reverify_v20 --archive-run YYYY/MM/DD/RUN-ATTEMPT --source-sha SOURCE_SHA --workflow-sha WORKFLOW_SHA . The pins are required inputs, not automatically trusted merely because a caller supplies them. This is an opt-in single-run verification bridge requiring gh and access to Sigstore verification; it does not run new network verification in ordinary synthetic CI. Six synthetic regression methods test the control flow with mocks; no actual cryptographic verification is claimed. Existing archives and production unchanged. HOLD/DISABLED.
